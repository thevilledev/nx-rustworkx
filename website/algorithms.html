Automatic-dispatch policy

Explicit backend="rustworkx" calls can reach every implementation above. Automatic backend priority declines 20 functions for which conversion or result remapping is usually slower than NetworkX:

  • Early exit favors NetworkX: has_path, bidirectional_shortest_path, descendants_at_distance, is_bipartite.
  • Python result construction dominates: complement, all_pairs_shortest_path, the single_source_* and single_target_* path variants.
  • The kernel is cheaper than remapping: degree centrality variants, cycle_basis, negative-cycle discovery, weak connectivity, and single_source_dijkstra.

Single source-target and unweighted forms of shortest_path and shortest_path_length are also declined automatically.

Compatibility limits

The backend rejects argument shapes it cannot honor:

  • No MultiGraph or MultiDiGraph.
  • No callable weight functions.
  • No cutoff on shortest-path functions.
  • Betweenness and closeness are unweighted; betweenness has no k= sampling.
  • Isomorphism is structural; node_match and edge_match fall through.
  • greedy_color implements largest_first only.
  • max_weight_matching requires integer edge weights.
  • A* requires a consistent heuristic. Disable the check with nx.config.backends.rustworkx.astar_heuristic_check = False only when you already know it is consistent.

Valid differences

When an answer is not unique, rustworkx may return a different valid ordering or structure. This applies to topological order, longest DAG paths, cycle bases, some predecessor maps, negative-cycle starting nodes, and minimum spanning forests with tied weights. PageRank, HITS, Katz, and eigenvector centrality may differ slightly through floating-point ordering.

Graph-returning functions return real NetworkX graphs. Backend metadata publishes per-function caveats, so help(nx.function_name) shows the relevant constraints after installation.
